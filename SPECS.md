# Specification

This document records the behavior baseline and confirmed requirements implemented in version 0.3.0. Future behavior changes require explicit requirements and human confirmation under `AGENTS.md`.

## Purpose and scope

Support match announcers by preparing historical player lists for both sides of selected BWHV fixtures and exporting printable Excel sheets. Historical lists are preparation aids; the actual lineup requires confirmation at the venue.

## Existing behavior and acceptance checks

1. Settings are loaded from `parameters.json`: configured teams and league URLs, season, ISO match date, output path, optional history limit, and refresh flag. The output path supports `{next_date}` substitution.
2. Completed league results are persisted in a JSON cache per configured label. Successful reports are reused by PDF ID; missing or failed reports are attempted again, and refresh also reparses successful reports. Cache schema and league identity mismatches raise an error.
3. PDF parsing retains zero-goal players, officials, roster statistics, ordered event text, and structured event fields. Unrecognized action text is retained with an error marker. Missing readable rosters or events reject the report.
4. For a configured team, the selected date yields the earliest non-cancelled fixture with a known kickoff. No fixture on that date yields no preparation for that team.
5. Each side's history selects earlier completed or cancelled fixtures, optionally limited to the latest positive integer number of fixtures. Cancellations count toward that limit and are not replaced by older played games. Only readable reports from played fixtures contribute player statistics. Missing reports are reported and do not cause older matches to fill that limit. Goals and roster appearances accumulate by normalized player name.
6. Console preparation text includes report availability, source matches and links, player totals, officials, and handled errors. A handled failure for one configured team allows processing of other teams.
7. Excel export includes a player worksheet and a standings worksheet per available preparation on the selected date. The player page contains both teams' player statistics, five blank addition rows per team, and the season scorer ranking. Sheets use A4 portrait printing fitted to one page. No selected preparations means no workbook write.

## Confirmed standings and printing requirements

- Make complete scorer-ranking rows bold for players from either participating team; other clubs remain regular. Use `Rg.` for the compact rank header. Match league-table header alignment to the content: numeric columns right-aligned and team names left-aligned. Center both upcoming-fixture home/away labels, retaining bold styling for home games.
- Use compact 18-point base row heights throughout the standings/history/upcoming sheet, with additional height for wrapped text and smaller spacer rows. Preserve the player sheet's 21.5-point player and five fill-in row heights for handwritten notes.
- Compact the player page by removing spacer rows around its header and scorer ranking and reducing excess row height. Retain all player/scorer rows, the five blank addition rows per team, existing data font sizes, and A4 portrait fit-to-one-page settings. Allow extra height for wrapped fixture details, player/club names, and report-coverage notes rather than clipping those labels.
- Start each player page with `Matchblatt` and the league name, followed by the selected fixture's date, kickoff, and home/away teams, then `-- powered by https://github.com/trichie/handball_bwhv`. Make the project URL clickable. Keep the player tables, five blank addition rows per team, and scorer ranking below this heading within the same A4 print page.
- Add a league-wide season scorer ranking below both player lists and their blank addition rows on the same A4 player page. Aggregate every readable report for completed, non-cancelled league games with known kickoffs strictly before the selected fixture, independently of `n_matches`. Group players by fixture club and name with jersey-change annotations removed, retaining separate records for namesakes at different clubs. Sum roster appearances, goals, scored seven-metre goals, yellow cards, two-minute suspensions, and red cards.
- Use `scorer_top_n` (default 10) for the number of league leaders and `scorer_per_team` (default 3) for each participating team's minimum number of best scorers, adding team scorers only if not already shown, without duplicates, retaining their league ranks and overall goal order. Equal goals share competition ranks (1, 1, 3); club and player names determine stable display order and the configured league-player cutoff. Both scorer parameters must be positive integers; booleans, null, zero, negatives, and non-integers are rejected. Omitted parameters use their defaults. These selection counts do not change the season-wide aggregation period. Fewer available players yield fewer rows. Columns are `Rg.`, `Spieler (Verein)`, `Spiele`, `Tore (7m)`, `Gelb`, `2 min`, `Rot`. Include readable-report counts and an incompleteness warning for missing/failed eligible reports. Missing ranking data or empty player data must be stated explicitly.
- Arrange each standings page vertically as the league table, both teams' history tables side by side at equal widths with one blank column between them, then the configured team's upcoming fixtures across the full width. Align the two history headers and newest rows. Place upcoming fixtures below the longer history, retaining all selected rows, cancellation comments, and empty-history messages. Shared row heights accommodate the longer wrapped text on either side.
- For each listed player, retain the starting jersey number from that player's most recent readable appearance in the selected history. Use the first number in a published jersey-change annotation; otherwise use the roster number. Older appearances must not overwrite it.
- Add upcoming fixtures for the configured team only after both teams' history sections on the standings page. Exclude the selected match; select later scheduled fixtures with known kickoffs, excluding live, completed, and cancelled games. Sort earliest first and include every fixture through the next home game, including that home game, or all remaining fixtures if no home game remains. This selection is independent of `n_matches`. Show date, kickoff, home/away teams, and a clear home/away indicator; show an explicit message if no later scheduled games remain. Retain the same A4 page and player/standings sheet pairing.
- Include cancelled fixtures in chronological history using the same known-kickoff cutoffs as completed games. They count toward `n_matches`; `null` includes all eligible completed and cancelled fixtures. Show `Abgesagt` and the published cancellation comment instead of a score in Excel, and identify cancellation in console output. Do not download their PDFs or count player statistics. Persist cancelled games even without numeric scores, storing unavailable goals as `null`. A cancelled upcoming fixture remains excluded from match selection.
- Player tables use `Nr.`, `Spieler`, `Spiele`, `Tore (7m)`, `Gelb`, `2 min`, `Rot` in that order. Goals display total goals with scored seven-metre goals in parentheses, for example `42 (8)`. Seven-metre goals, yellow cards, two-minute suspensions, and red cards are summed across the same selected readable reports as goals and roster appearances. Both teams and their blank addition rows remain within the player sheet's one-page A4 print area.
- Use the latest official league table available when synchronizing, regardless of the future fixture date. Preserve all teams, official order, and source fields without reconstructing standings from match results.
- Store a `league_table` snapshot in each league JSON with `retrieved_at`, `rows`, and `error`. Replace it on every successful league API fetch, independently of report refresh. Missing or unreadable standings replace the previous snapshot with empty rows and an explicit error; a failed HTTP fetch leaves the existing cache untouched.
- Export a separate standings worksheet per exported match, showing league name, retrieval time, position, team, matches, wins, draws, losses, goals, goal difference, and points. Report unavailable standings in the console and on the standings sheet while preserving player-sheet export.
- Configure every worksheet with its own print area, A4 portrait paper, and scaling to one page wide by one page tall. Users can edit the workbook before exporting the entire workbook to PDF. Edits outside a print area require extending that area; automated PDF generation is outside this change.
- Keep preparations in configured team order, with each player sheet immediately followed by its standings sheet, including an unavailable-standings sheet when needed. These consecutive page pairs support printing players on the front and standings on the back of each sheet of paper.
- Below the standings, include a result section for each of the two teams using the same selected match history as player preparation. `n_matches` limits each team's results; `null` includes all eligible games. Show date, home team, away team, and final score, newest first, even when a game's PDF is missing or unreadable. Show an explicit message for teams with no prior games. Include both sections in the same one-page A4 print area, without truncating history; large histories may reduce printed readability.

## Boundaries

The current scope does not include guaranteed upcoming lineups, playing-time measurement, OCR, a graphical interface, or fully offline fixture preparation. Public report availability and layout constrain completeness. See `PROJECT.md` for implemented data contracts and limitations.

## Open requirements

Automated acceptance coverage has not yet been established as a persistent test suite.
